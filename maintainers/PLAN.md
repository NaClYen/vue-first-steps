# vue-first-steps 計畫書

給「會 JavaScript、沒碰過 Vue」的工程師，用視訊會議（分享單一視窗）帶領，目標是讓他們能順著 [react-to-vue](https://github.com/NaClYen/react-to-vue) 的《從畫面讀 Vue》（`docs/reading-guide.html`，手寫的圖解頁）讀下去。

本計畫由初稿加上兩輪審查（Opus）整理而成。進度與任務見 [TASKS.md](TASKS.md)。

## 1. 已定案的決定

| 項目 | 決定 |
| --- | --- |
| 路線 | JS → Vue。完全不教 React；舊的 React 系統只是參考資料 |
| 對象 | 會 JS 基礎的工程師，沒碰過 Vue |
| 形式 | 視訊會議，講師分享單一視窗；可錄影 |
| 每場時間 | 30 到 60 分鐘，場次數依內容而定（見第 3 節） |
| 可用工具 | StackBlitz、play.vuejs.org；公司網路是否擋其他網域尚未實測（見第 8 節 M1） |
| 協助者 | 可以找第二位協助者，但每次使用都要有理由（見第 5 節規則） |
| 學員 JS 基礎不足 | 不另加補強場，也不做課前小測驗；請本人用 AI 輔助自學（2026-10-12 決定） |
| 公司環境 | 依 react-to-vue 的經驗，工具基本上都可執行（2026-10-12 使用者確認）；不同之處另行測試（見 TASKS M1） |
| 專案關係 | 另開 repo；連結指向 react-to-vue 的**標記版本**（目前 `V1.0`），不指向 `main` |
| 開發 | 直接在 `main` 開發（2026-10-12 決定） |
| 專案結構 | 輸出（`sessions/`、`shared/`、`facilitator/`）與維護（`maintainers/`）分開（見第 8 節） |
| 維護方式 | 由 AI agent 維護；內容用繁體中文 |
| 提交署名 | commit 作者用使用者自己的 git 身分，訊息不加 Claude 署名 |

## 2. 離開條件（結業標準）

「能順著 reading-guide 讀下去」要變成可以遠端檢查的條件。分兩部分，都通過才算完成。

### A. 實作（S6，現場，40 分鐘）

不靠 AI（可看官方文件），在提供的起始專案做出 TODO list，交出 play.vuejs.org 分享連結。五項各自判定：

1. 能新增
2. 空白或全空白字串被拒絕
3. 能刪除
4. 能勾選
5. 剩餘數量正確

五項全過才算過；四項加補考通過也算。補考才用帶回家的方式。**不放水**：沒過就請對方補做 S3 到 S5 再考。

加分（不影響通過）：篩選、`key` 用穩定 id、剩餘數量用 `computed` 而不另外存。

### B. 讀碼（S8，筆試或口頭）

給一份附註解的 `RuleListView.vue`，回答 5 題，答對 4 題算過：

1. 狀態放在哪裡
2. 什麼觸發 `load`
3. 從按下查詢到載入的路徑（`submit` → `router.push` → `watch` → `load`）
4. 載入與錯誤狀態怎麼顯示
5. `RocMonthInput` 收進什麼、回報什麼

> 目標是「能在註解輔助下說明資料流」，不是「輕鬆讀完 276 行」。那個檔案有網址改寫、請求取消、半填年月等細節，初學者不需要全懂。

## 3. 課程大綱

每場一個主要區塊加一個小區塊。預設 45 分鐘；結業檢查與導讀場次 60 分鐘。**時間預算不留零緩衝**：開連結、麥克風、提問每場至少耗 3 到 5 分鐘，所以區塊不要塞滿。

| 場次 | 時間 | 內容 |
| --- | --- | --- |
| S0 課前（非同步） | 約 10 分鐘 | 在**公司筆電與公司網路**實際開三個連結並貼截圖 |
| S1 | 45 | 看懂 `.vue` 檔：`<script setup>`／`<template>`、`{{ }}`、`@click`、`ref` 與 `.value` |
| S2 | 45 | `reactive`、`v-model`、`@submit.prevent`；怎麼讀錯誤訊息與瀏覽器主控台 |
| S3 | 45 | `v-if`／`v-else`、`v-for` 加 `:key`、`computed`（TODO 的剩餘數量用得到） |
| S4 | 45 | 元件：props、emit、元件的 `v-model`；TODO 第一部分（列表與新增） |
| S5 | 45 | TODO 第二部分（刪除、勾選、剩餘數量；篩選為加分） |
| **S6 結業檢查 A** | 60 | 現場 40 分鐘做 TODO，20 分鐘講評 |
| S7 | 45 | `async`／`await`、`fetch`、載入與錯誤狀態、`watch`、路由基礎（`route.query`、`router.push`、`RouterLink`、路由守衛是什麼）、模擬服務（MSW）是什麼。只點名「只保留最新一次回覆」，不教 |
| **S8 結業檢查 B** | 60 | 15 分鐘讀 TypeScript 型別標註，再導讀附註解的 `RuleListView.vue`，最後做讀碼題 |
| S9 交棒 | 45 | 一起開啟 `reading-guide.html` 第 1、2 節，說明怎麼略過「React 對照」，並指向 `no-react-start.html`（給沒有 React 基礎者的說明頁） |

### 必須補上的內容（初稿曾漏掉）

這些只出現在真實專案裡，玩具 TODO 不會碰到：路由基礎、元件的 `v-model`（`modelValue` 加 emit）、`watch` 加 `immediate`、`onBeforeUnmount`、MSW。

### 刻意不教

- 「Vue 為什麼可以直接改狀態」：那是和 React 對比才有的題目。
- 請求取消與網址當狀態：只在 S7 點名，S8 導讀時看到再說明。
- React 的任何東西。

### 本機安裝不是正式場次

Node、`npm ci`、`npm run dev` 要處理公司代理與憑證問題（見 react-to-vue 的 `docs/troubleshooting.md`）。改成**課前準備加一場「安裝診所」**（約第 2 週，由協助者帶），讓問題提早幾週暴露，S9 才不會卡在環境。

## 4. 視訊會議的做法

- **示範後再做，不跟著打**：講師示範時學員只看，示範完切到自己視窗做練習。題目寫在起始專案的註解裡，學員不用回頭看共享畫面（解決「同時看分享與寫程式」的兩視窗問題）。
- **重複程式碼用貼的**，只現場打最關鍵的 3 到 5 行。
- **找出卡住的人**：一張進度表（人名 × 步驟，綠燈打勾）加會議的表情符號；卡住的人拉去分組討論室，不拖慢全班；**絕不在共享畫面上除錯**。
- **共享方式**：只分享單一視窗、關閉通知；螢幕 1920×1080、縮放 125 到 150%、編輯器字體 22 到 24px、淺色高對比；中文字型用微軟正黑體或 Noto Sans TC；一個畫面不超過約 25 行。
- **每步有明確的通過訊號**：視覺化的檢查清單或測試轉綠；練習後做一次進度投票。
- **示範預錄**：試行時先預錄示範影片，直播錄影當備援。

## 5. 第二位協助者：何時需要

**需要協助者**（符合任一條）：

1. 學員要現場跑程式，且人數超過 5 人。
2. 場次是環境安裝（安裝診所）。
3. 計時的結業檢查（S6、S8），為了公平與處理工具故障。

**理由**：主講者一旦停止共享畫面去幫某個人除錯，其他人就整個停下來。每個卡住的人約耗 3 到 5 分鐘——**這個數字要在試行時實測，不先當作事實**。

**不需要**：只有示範或導讀的場次，或 5 人以下。

**協助者的工作**：在分組討論室或私訊解卡、管進度表與聊天室、掌控時間。成本是場次時間加約 15 分鐘準備。

**沒有協助者時的做法**：每一步都附「卡住了」連結，直接跳到該步驟的解答；問題留到課後 10 分鐘答疑；每次練習後做進度投票；用預錄示範。

## 6. 環境

| 工具 | 用途 | 風險與對策 |
| --- | --- | --- |
| play.vuejs.org | S1 到 S6 的單檔練習 | 從 CDN 載入 Vue，公司代理可能擋，**課前檢查必測**；網址格式沒有官方文件，可能改變，所以每週用無頭瀏覽器開一次產生的連結；長網址在聊天室可能被截斷，改發短連結；沒複製網址就關分頁會遺失，要教「複製網址就是存檔」 |
| StackBlitz | S7 到 S8 的多檔案範例 | 需要較新的 Chromium；公司代理常擋其網域；每次開啟都跑 npm 安裝；固定 `package.json` 版本 |
| 備案 | 單檔 HTML 加內嵌的 `vue.global.js` | 可直接從 `file://` 開，完全不需要 npm |

**Vue 版本固定為 3.5.43**，與 react-to-vue 一致。

> 2026-10-12 實測：play.vuejs.org 的 `?vue=版本` 參數無效，預設載入站上目前部署的 Vue（來自 play.vuejs.org 自己的網域，不經第三方 CDN；目前剛好是 3.5.43）。所以連結不帶版本參數，改由每週檢查核對版本；要硬性固定，得在專案加 `import-map.json` 指向 CDN，取決於 M1 的實測。

## 7. 錄影

- 邀請信與開場各說明一次；鏡頭可選；分組討論室不錄。
- 專用瀏覽器設定檔、關閉通知、聊天室不上畫面；不出現內部網址、權杖、客戶資料。
- 剪輯：講師在進度表記下「Step N」的時間點，用 `ffmpeg -ss … -to … -c copy`（不重新編碼）剪成每步 3 到 5 分鐘；字幕用會議工具的逐字稿。

## 8. 新 repo 的做法與建置順序

### 結構

分成「輸出」（交付給講師與學員）與「維護」（只給維護者與 agent）兩邊：

```text
vue-first-steps/
├── README.md、CLAUDE.md
├── sessions/NN-名稱/               輸出：學員看得到
│   ├── index.md                    唯一來源；轉成示範頁（大字、逐步）
│   └── steps/NN/{starter,solution,test}
├── shared/                         輸出：從 react-to-vue 標記版本複製的樣式與腳本，附來源與雜湊
├── facilitator/                    輸出：只給講師。講師手冊、進度表、評分表
├── dist/                           建置結果（不進 git）
├── maintainers/                    維護
│   ├── PLAN.md、TASKS.md
│   ├── package.json、vitest.config.mjs   相依套件只裝在這裡
│   └── tools/                      產生 play.vuejs.org 連結、產生差異、轉換 HTML、檢查
└── .github/workflows/              CI
```

- 題目寫在每一步 `starter` 的註解裡，用 `@task-start`／`@task-end` 夾住。「starter = 上一步 solution」的檢查會忽略這些區塊，產生差異時也不算。
- 步驟測試（`test/`）放在 `sessions/` 內，但由 `maintainers/` 的 vitest 執行，所以學員 ZIP 不需要 `node_modules`。

- 示範頁由 Markdown 產生（沿用 react-to-vue 的 `docs-build` 作法），**不手寫 HTML、不做投影片**。
- 每一步的差異由前後步驟**自動產生**，不手寫。
- 每一步的 `.vue` 檔是**唯一來源**，由腳本產生 play.vuejs.org 連結（固定 Vue 版本）。
- 共用資源複製進 `shared/`，記錄來源標記並用雜湊值檢查；**不用 git submodule**（初學者、ZIP、agent 都容易混亂），**不發 npm 套件**（會碰到公司 registry 問題）。

### 每一步必須通過的檢查（讓 agent 維護時不悄悄壞掉）

1. 用 `@vue/compiler-sfc` 編譯。
2. 用 vitest 與 `@vue/test-utils` 掛載並跑測試（測試同時是學員的自我檢查）。
3. 產生的連結能解回原檔（來回一致）。
4. 每個起始專案 = 上一步的解答（差異只能是 `@task` 題目註解），由 CI 強制。

### 建置順序

| 里程碑 | 內容 | 驗證 |
| --- | --- | --- |
| **M0** | repo 骨架、連結編碼與解碼、版本固定、CI | CI 綠燈 |
| **M1（關卡）** | 在**公司筆電與公司網路**測 play.vuejs.org、CDN、StackBlitz、npm registry。2026-10-12：使用者依 react-to-vue 的經驗確認基本上都可執行，不同之處另測 | 不過就調整工具選擇，**不繼續做內容** |
| **M2** | 做 S1、S2、進度表、評分表；找 2 到 3 人試行（一位 JS 強、一位弱、一位用受限制的筆電） | 量各步實際分鐘數、卡點、能否只看分享就跟上 |
| **M3** | 依試行修正（預期時間要多約三成），再做 S3 到 S6 | 結業檢查 A 冷試一次 |
| **M4** | 做 S7 到 S9、安裝診所、給沒有 React 基礎者用的《reading-guide》說明頁 | 沒參加過試行的人冷試 |
| **M5** | 第一梯次、檢討、整理短片庫 | 梯次檢討記錄 |

### 選配（不在第一版）

自動批改：從提交的 play.vuejs.org 連結解出 `App.vue` 再跑測試。學員的程式碼不可信，需要隔離環境（無密鑰、無網路、有逾時）。第一批試行期間靠講師人工驗收。

## 9. 與 react-to-vue 的關係

- react-to-vue 現在的 `reading-guide.md` 與 `react-vue-comparison.md` **預期讀者認識 React**。沒有 React 基礎的人會卡在「React 對照」方塊與詞彙。
- **最大風險**：玩具 TODO 與真實專案之間有落差。路由、`watch` 加 `immediate`、「只保留最新一次回覆」、TypeScript、MSW 都只出現在真實程式碼裡。對策：S7 提前教路由與 `watch`；S8 導讀附註解的真實檔案；M4 做一頁給沒有 React 基礎者的說明。
- **對 react-to-vue 的小修改（2026-10-12 使用者同意並授權）**：加一頁給沒有 React 基礎者的說明（`docs/no-react-start.html`），告訴他們跳過「React 對照」並附詞彙表。已推到 react-to-vue 的 `main`（commit `2a9f6dc`），待打標記 `V1.1`（見 TASKS D6）。
